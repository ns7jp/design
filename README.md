# 設計書基礎演習案件パック

未経験からサーバー構築エンジニアを目指す人向けのポートフォリオです。架空企業「**株式会社サンプル物産**」(卸売業・従業員60名)の社内ITインフラ刷新案件を題材に、要件定義から運用保守までの設計書一式を、実務の体裁を保ちながら**初心者が読んでも理解でき、理由まで理解して自然に覚えられる**ように作成しています。

> 登場する企業・数値・IPアドレスはすべて演習用の架空設定です(WANの例示IPアドレスにはRFC5737のTEST-NET-3を使用しています)。文書内の担当者名・日付・レビュー履歴も演習用の記入例を含み、実顧客への納品・検収実績を示すものではありません。

## 採用ご担当者様へ：成果物と実施状況

**このリポジトリで確認できる成果物は、要件・設計理由・構築手順・試験条件をつなぐ13文書の教材です。** 2026年9月11日時点の公開資料で確認できる範囲を示します。

| 区分 | 現在の状態 | 確認できる内容 |
| --- | --- | --- |
| 設計書・教材 | 作成済み | 架空案件の要件定義から運用保守までの文書、構成図、パラメータ、確認手順 |
| 本人によるVM構築・試験 | 実行証跡未掲載（実施状況未確認） | [テスト仕様書](docs/10_テスト仕様書.md)の実施結果欄は未記入。期待結果は合格記録ではありません |
| 本人による設計判断の説明 | 説明記録未掲載 | 教材の解説・面接例と、本人が独力で説明できた記録を区別します |
| 本番環境・長期運用 | 実績として未確認 | 「本番想定」の構成、RTO/RPOは設計条件であり、稼働・復旧の実測値ではありません |

短時間で見る場合は、[案件の課題と目的](docs/01_プロジェクト概要書.md) → [全体構成](docs/03_基本設計書_システム構成編.md) → [試験条件と実施結果欄](docs/10_テスト仕様書.md) の順にご覧ください。別構成で本人が実施したサーバー演習は、[serverの検証証跡台帳](https://github.com/ns7jp/server/blob/main/docs/evidence/README.md)にまとめています。この9台構成の実施証拠としては扱いません。

次の確認は、小さな構成を一つ選び、本人が「なぜその設定にしたか・何を見て正常と判断したか・失敗時にどう戻すか」を実行結果と合わせて記録することです。[学習ガイド](docs/13_学習ガイド.md)の記録欄を利用できます。

## このポートフォリオの読み方のポイント

- 各文書の冒頭に **📘 学習ポイント**(この文書が実務で何のために使われるか)を用意しています。
- 本文中の要所に **💡 なぜこう設計するのか**(設計の意図・理由)を挟み、暗記ではなく理解を優先しています。
- 専門用語は初出時に簡潔な説明を添え、[用語集](docs/12_用語集.md)を随所から参照できるようにしています。
- IPアドレスやサーバ一覧などの数値は、DOC-01〜DOC-13で共通の設計値として記載しています。文書の整合確認と、VMで設定が動作することの確認は別に記録します。
